## The Core Problem in One Sentence

FortiGate's proxy rewrites your JavaScript looking for URLs to redirect through itself — and it corrupts `.map().join('')` because the pattern *looks like* URL-building code to its dumb text scanner.

---

## The 4 Rules to Never Break

| Rule | ❌ Don't | ✅ Do |
|---|---|---|
| **Build HTML** | `arr.map(fn).join('')` | `for` loop + string accumulator |
| **String content** | `` `<tag>${val}</tag>` `` → `innerHTML` | `'<tag>' + val + '</tag>'` |
| **Button events** | `onclick="fn(${id})"` | `data-id="${id}"` + `addEventListener` |
| **Scripts** | Inline `<script>` in EJS | External `/public/js/file.js` |

---

## How to Spot It Fast

Open DevTools → Console. If you see:
- `SyntaxError: Unexpected token ')'` → FortiGate added an extra paren
- `SyntaxError: Unexpected end of input` → FortiGate broke a string
- View page source and search for `fgt_sslvpn` to confirm

## Quick Scan Command
```powershell
Get-Content ".\public\js\yourfile.js" | Select-String "\.join\(''\)"
```
If it finds any hits → that file will break through the proxy.
