DEFERRED-01 — JWT browser storage [RESOLVED]
===============================================================================

Priority: Resolved before the NEXT baseline
Status: Complete; verified again by the 2026-07-21 staging hardening smoke.

Resolution:
- Login uses the server-set HttpOnly `rxToken` cookie.
- Application JavaScript does not write the session JWT to localStorage or a
  JavaScript-readable cookie.
- API requests use credentialed cookies, and logout clears server cookie state.
- The staging security hardening smoke confirms this boundary in source and the
  live staging response.

DEFERRED-03 — uuid moderate vulnerability through Sequelize
===============================================================================

Priority: Low — monitor only
Status: Open, not urgent. Do NOT use npm audit fix --force.

Background:
- npm audit reports 2 moderate vulnerabilities:
  - uuid < 11.1.1 through sequelize dependency chain
- Running npm audit fix --force would force a breaking Sequelize major version upgrade.
- Sequelize major upgrades affect models, migrations, associations, and query behavior.

Action plan:
  1. Monitor Sequelize releases at: https://github.com/sequelize/sequelize/releases
  2. When Sequelize releases a patch that resolves the uuid transitive dep without breaking
     changes, test the upgrade in a branch first:
     - npm install sequelize@<new-version>
     - Run migrations on a copy of the production DB
     - Test: login, patients, RX records, reports, backups, system settings, audit log
  3. Do NOT run npm audit fix --force on production code

Current known safe state: app functions correctly despite advisory.

DEFERRED-05 - Backoffice release visibility and controlled update handoff
===============================================================================

Priority: Medium
Status: Proposed for a staging-first implementation after v4.0.0-next.25.

Goal:
- Let an Administrator see the installed version, newest official GitHub
  release, release notes, CI/checksum status, and whether an update is
  available from Backoffice.
- Keep Project Control as the privileged update engine for database backup,
  migration, .env preservation, Windows service stop/start, health validation,
  and rollback.

Safety boundary:
- Do not give the web-server process PostgreSQL maintenance credentials or
  Windows service-control privileges.
- Do not let an HTTP request replace the running executable directly.
- A future Backoffice action may download/verify an official package and create
  an audited pending-update request, but an Administrator must complete the
  privileged operation through Project Control (or a separately designed,
  least-privilege local updater service).

Required staging tests:
- GitHub unavailable, rate limited, malformed response, missing assets, and
  checksum mismatch all fail closed without changing the installation.
- FortiGate/Cloudflare access cannot bypass Administrator/master permissions.
- Current users and calls continue normally while checking for updates.
- Rollback instructions and the currently installed version remain visible.
